# One Line, One World

### Une personne. Une ligne de code. Un monde créé ensemble.

Et si des développeurs, des débutants et des personnes qui créent avec l'IA construisaient une application open source… une seule ligne à la fois ?

**Le défi : chaque personne peut faire accepter une seule ligne de code pour tout le projet.** Choisis-la bien : elle peut ajouter une idée, améliorer l'expérience ou résoudre un problème. L'IA est bienvenue, mais elle ne donne pas droit à des lignes supplémentaires : la personne qui soumet la contribution en est responsable.

## Le projet

Nous construisons une petite expérience web collective : un ciel à explorer, que la communauté fera évoluer ligne après ligne. Le point de départ est volontairement simple. Les fonctionnalités futures émergeront des idées et des contributions de chacun.

Ouvre `index.html` dans ton navigateur pour l'essayer. Aucun compte, installation ou serveur n'est nécessaire pour jouer avec la version locale.

## Comment contribuer

1. Crée un compte GitHub si nécessaire, puis fais un **fork** de ce dépôt.
2. Dans `src/experience.js`, ajoute **une seule ligne physique** de JavaScript à l'intérieur de `start()` ou modifie **une seule ligne existante**. Ne modifie pas les autres fichiers dans cette pull request.
3. Teste en ouvrant `index.html`. Vérifie que ta ligne fonctionne, est lisible et respecte les règles ci-dessous.
4. Propose une **pull request** vers `main` et explique en quelques mots ce que fait ta ligne. Attends la revue avant sa fusion.

Jamais utilisé GitHub ? Sur ton fork, ouvre `src/experience.js`, clique sur le crayon pour modifier, enregistre ton changement sur une branche, puis utilise « Contribute » / « Open pull request ». Tu peux demander de l'aide dans une issue sans dépenser ta ligne.

### Les règles du jeu

- Une seule ligne de code **acceptée par personne pour toute la durée du projet**, pas une ligne par jour ni par pull request. Une proposition refusée ne consomme pas ta participation.
- Une modification remplace au plus une ligne par une ligne ; une addition ajoute une ligne sans en supprimer. Pas de changement d'autres lignes ou fichiers dans la même pull request.
- La ligne doit être lisible : pas de code compressé, de lignes artificiellement interminables, d'obfuscation ni de contournement de la limite. Un maximum de 160 caractères est recommandé.
- Pas de secrets, collecte de données, traçage, publicité intrusive, code malveillant ou dépendances externes. N'ajoute que du code que tu as le droit de partager.
- Humain ou IA : la personne qui propose la pull request est responsable du code. Un agent ou un autre compte ne permet pas de contourner la règle.
- Les idées, discussions, signalements de bugs et revues sont les bienvenus sans limite dans les issues et les pull requests. La première version et ses fichiers de configuration servent de fondation au défi.
- Les mainteneurs examinent le code, sa sécurité et sa cohérence avant fusion. La fusion n'est pas automatique. Une vérification aide à compter les lignes et les contributions par compte GitHub, mais ne peut pas vérifier l'identité réelle ni remplacer la revue humaine.

## Inspiration

Fais scintiller une étoile, change une couleur à un moment précis, invente une interaction ou un petit message. Pars d'une idée simple et regarde ce que ta ligne peut apporter aux autres.

## English: one person, one line, one world

An open-source web experiment built together. Each person may have **one physical line of code accepted in total**, whether written by hand or with AI. Fork the repository, add one line (or replace one line) in `src/experience.js` inside `start()`, test `index.html`, and open a pull request explaining your idea. Ideas, discussions and reviews don't use your line. Maintainers review safety and clarity; automated checks are only an aid and cannot verify a real person's identity. MIT licensed.
